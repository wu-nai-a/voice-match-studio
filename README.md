# Voice Match Studio

这是一个纯静态网页：导入角色 XLSX、浏览/试听音色资源、自动推荐成熟声线、手动调整，并导出带 `匹配voiceId` 列的结果。

## 首次使用

1. 打开网页后可先点“先试用测试集”，查看女声、男声角色的推荐、试听、手动调整与导出流程。
2. 正式使用时先导入角色 XLSX；如果表内有 `性别` / `gender` 列会优先按该列路由，混合男女表逐行处理。
3. 在角色右侧用“推荐音色”试听前三条，或点“手动调整音色”跳到同性交列表。手动列表中自定义音色始终置顶。
4. 导入角色表后会弹出匹配配置：默认是“偏成熟 + 按对应性别选择最匹配”，也可以改成偏幼态，或强制只在成熟/幼态音色中选择。

## 添加自定义音色

导入完整资源包时需要包含 `manifest.json` 和音频目录；支持 `.wav`、`.mp3`、`.m4a`、`.ogg`、`.flac`。如果手里只有音频文件，不需要懂 JSON，直接在左侧“只有音频也可以添加”选择一个或多个 `.wav`、`.mp3`、`.m4a`、`.ogg`、`.flac` 或 `.aac` 文件，网页会先打开确认窗口：

1. 文件名会作为默认名称；如果音频文件名能和资源包中的记录对应，会自动带出中文名称。否则请在“名称（建议中文）”中填写易懂的中文名。
2. `voiceId` 默认自动生成英文值，也可以自己修改；必须唯一，只允许英文、数字、下划线或短横线，例如 `custom_wen_rou_nv_01`。它是导出 XLSX 时唯一写入的值。
3. 确认后，新音色会标上“自定义”，在资源库和同性交的手动调整列表中置顶；已有角色的匹配结果不会被重算或覆盖。

网页里新增的文件只保存在当前浏览器会话。要把它加入 GitHub 的正式资源包，按 `assets/voice-package/README.md` 的流程复制音频文件并更新 `manifest.json`；其中 `voiceId`、性别、成熟度必须与网页确认的值一致。

## GitHub Pages 部署

1. 将 `web` 目录中的全部文件提交到 GitHub 仓库根目录，或将其作为 GitHub Pages 的发布目录。
2. 在仓库的 Pages 设置中选择 `main` 分支和发布目录。
3. 保留 `assets/voice-package` 整个目录。网页会自动加载其中的 `manifest.json` 及分类后的音频文件。
4. 当前资源包约二十余 MB；当音频资源持续增长并接近 GitHub 单文件或仓库体积限制时，改用 Git LFS 或对象存储，并在 `manifest.json` 更新播放地址。

## 匹配规则

- 优先读取表格的 `性别` / `gender` 列；混合男女角色会逐行匹配对应性别的成熟音色。
- 没有性别列且文本无法可靠识别时，角色会显示为“待确认”，需要手动选择性别后才会生成候选。
- 自动推荐默认排除 `幼态/年轻` 分类。
- 评分先综合角色简介、设定、开场白提取角色风格，再比较资源包中的 `profile` 声线参数，并用音色名称/ID 的声线标签做补充。页面显示的是资源库内的“适配指数”，不是概率；复用惩罚只用于选出更分散的结果，不会把显示分数扣低。
- 手动调整区固定展示当前角色对应性别的其余音色，并同时标注“偏成熟”或“偏幼态/年轻”，每条都可以试听和匹配。
- 资源绑定始终以最新 JSON 的 `voiceId` 为唯一主键；即使 URL 文件名和 ID/中文名称不完全一致，也只通过 manifest 的明确映射播放和导出。

## 声学分析

- 页面会在浏览器本地解码音频，提取基频、频谱重心（明亮度）、能量变化、活跃比例和过零率等可解释特征。
- 声学特征用于补充人设与资源库 profile 的匹配评分，占总评分 30%；同一句测试文本下，它主要帮助区分音高、厚度、明亮度、能量和稳定性等音色差异。
- 音频未找到、浏览器不支持解码或读取失败时，页面会显示“分析不可用”，并自动退回原有的人设/profile 匹配，不影响试听、手动匹配和 XLSX 导出。
